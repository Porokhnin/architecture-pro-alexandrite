# Мотивация
Компания уже потеряла несколько крупных контрактов из-за проблем с заказами. Недовольство пользователей растет. Если бы в системе уже был мониторинг, то можно было бы заранее подготовиться к возросшей нагрузке и мониторить ошибки в системе, тогда всех сопутствующих проблем бы не возникло. 
Внедрение мониторинга позволит:
- быстрее решать проблемы и повышать надежность
- повысить удовлетворенность пользователей
- повысить быстродействие системы и распределить ресурсы

Что для компании Александрит является приоритетом №1 на данном этапе развития бизнеса.

## Shop API
| № | Метрика | Ярлык | Комментарий |

| 3 |Number of HTTP 200 for shop API|instance||
| 4 |Number of HTTP 500 for shop API|instance|Позволяет отслеживать количество ошибок в приложении. Если количество превышает 5%, то это может служить сигналом о необходимости сбое в работе приложения.|
| 5 |Number of simultanious sessions for shop API|instance|Позволяет отслеживать количество сессий. Если количество начинает приближаться к максимальному (выявленному при нагрузочном тестировании), то это может служить сигналом о необходимости поднятии дополнительных инстансов приложения. |

# Дополнительное задание
Для API показателем насыщенности будет являться:

- CPU % for API - при превышении 80% необходимо поднимать дополнительный инстанс
- Number of simultanious sessions - при превышении 80% необходимо поднимать дополнительный инстанс
- Response time (latency) for API - если 95 персентиль превышает пороговое значение необходимо поднимать дополнительный инстанс

- Memory Utilisation for API > 90% - кидаем warrning группе эксплуатации
- Number of HTTP 500 for API > 5% относительно всех запросов за единицу времени  - кидаем warrning группе эксплуатации

Для DB:
- Size of MES db instance - чтобы не отказал сервис, если БД сильно разрастётся.
- Number of connections for db instance - число подключений ограничено и нужно поднимать команду DBA если мы приближаемся к лимиту. (возможно нет индекса) 

Для Messages Queue:
- Number of message in flight in RabbitMQ - показывает насколько забита очередь. И должен быть отправлен warrning группе эксплуатации, если длина очереди больше допустимого размера

Для S3 storage:
- Size of S3 storage - показывает объем занятого хранилища. И должен быть отправлен warrning группе эксплуатации, если использовано 90% объема
