Планирования трейсинга:
Трейсинг необходимо использовать тогда, когда есть межсервисное взаимодействие.
Основная проблема с заказами происходит при асинхронном взаимодействии MES API c CRM API посредством брокера сообщений Messages Queue.
Именно данные компоненты нуждаются в доработках с точки зрения трейсинга.


Мотивация:
Команда видит, что заказы часто находятся в непонятном состоянии или зависают на каком-то сервисе внутри IT-ландшафта. Внедрение трейсинга позволит точно находить место ошибки с наименьшими затратами. Что в свою очередь позволит:
- скорее найти и починить ошибки с заказами, что увеличит пользовательскую лояльность.
- тратить меньше времени разработчикам на баги, что позволит сконцентрироваться на развитии системы.
- закрывать больше фич за спринт, что в свою очередь увеличит объем "Value" поставляемый пользователям.
- снизить TTM, что позволит, быстро отвечать на изменения на рынке.

Предлагаемое решение:
Внедрение Jaeger. Доработка MES API, CRM API, Messages Queue для трейсинга. Архитектура отражена на схеме С4.


Компромиссы:
Трейсинг на текущий момент не принесет пользы для Shop API (можно обойтись логированием), так как Shop API не взаимодействует с другими сервисами.


Аспекты безопасности:
Доступ к трейсингу возможен только из контура компании. И соответственно из под VPN. Внедрение аутентификации и авторизации, с выделением наименьших прав для выполнения деятельности. Маскирование персональных и чувствительных данных. Передача данных по защищенным каналам связи TLS.
